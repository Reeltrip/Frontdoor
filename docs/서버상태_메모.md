# 서버 상태 관리 메모

서버에서 받아오는 데이터는 TanStack Query로 관리해요. 이 문서는 BE API 형식이 정해지기 전에 FE에서 정한 내용과, 확정되면 바꿀 곳을 정리한 거예요.

## 구조

| 파일 | 하는 일 |
| --- | --- |
| [client.ts](../src/shared/api/client.ts) | 모든 요청의 시작점이에요. 기본 주소와 JSON 처리를 맡고, 실패하면 항상 `ApiError { status, code, message, details }`를 던져요 |
| [fake.ts](../src/shared/api/fake.ts) | 가짜 응답을 지연시켜 돌려줘요 |
| [viewStatus.ts](../src/shared/api/viewStatus.ts) | 쿼리 상태를 `loading`·`error`·`empty`·`success` 하나로 바꿔요 |
| [queryClient.ts](../src/app/providers/queryClient.ts) | 공통 설정이에요. 4xx는 재시도하지 않고, 창을 다시 볼 때 새로 불러오지 않아요 |
| `features/*/api/*.ts` | 엔드포인트 함수와 쿼리 키(`placeKeys`, `sourceKeys`, `planKeys`)를 둬요. 쿼리 키는 여기서만 만들어요 |
| `features/*/api/*.fake.ts` | 가짜 저장소예요. 메모리에만 있어서 새로고침하면 처음 상태로 돌아가요 |
| `features/*/model/use*.ts` | 화면에서 쓰는 훅이에요 |

사용 예는 `/dev/components`의 `useSourceStatus`·`usePlaces`·`usePlan`에 있어요([ServerStateWidgets.tsx](../src/pages/ComponentTestPage/ServerStateWidgets.tsx)).

## 가짜 응답 ↔ 실제 서버

`.env.example`을 `.env`로 복사해서 바꿔요.

- `VITE_USE_FAKE_API`가 없거나 `true`이면 가짜 응답을 써요(지금 기본값).
- `false`이면 `VITE_API_BASE_URL`로 요청해요.
- Vercel에서는 프로젝트 환경 변수에 같은 이름으로 넣어요.

BE 형식이 정해지면 바꿀 곳:

1. `*.types.ts`의 "가짜 형식" 타입을 BE 형식으로 바꿔요.
2. [client.ts](../src/shared/api/client.ts)의 에러 응답 모양과 에러 코드 이름을 맞춰요.
3. 다 연결되면 `*.fake.ts`를 지워요.

## 기능명세서 예외 상황 → 처리할 곳

예외 상황은 PR #5(`feature/#4-exception-spec`)에 있어요. 처리 코드는 #9(`feature/#9-exception-handling`)에서 만들었고, 화면이 아직 없어서 훅·안내창·가짜 응답까지만 있어요. `/dev/components`의 "예외 안내 문구"부터 "기간 변경"까지에서 눌러 볼 수 있어요([ExceptionWidgets.tsx](../src/pages/ComponentTestPage/ExceptionWidgets.tsx)).

- 안내 문구는 [exceptionMessages.ts](../src/shared/lib/exceptionMessages.ts) 한 곳에 있어요. `<ConfirmModal {...EXCEPTION_MODALS.duplicateSource} ... />`처럼 펼쳐 넣어요.
- '아니요'가 데이터를 지우거나 되살리는 안내창(이미 있는 장소, 삭제된 카드)은 `isDismissible={false}`로 바깥을 눌러 닫히지 않게 해요.

| 예외 | 쓰는 곳 | 어떻게 |
| --- | --- | --- |
| 5-1 중복된 링크 | `useCollectSources` | `duplicateUrl`이 있으면 안내창. '네' `recollectDuplicate`(isForced로 다시 보냄), '아니요' `skipDuplicate`. 중복이 여러 개면 하나씩 물어요 |
| 5-1 여러 링크 동시 수집 | `useCollectSources` | 링크마다 따로 요청(`Promise.allSettled`). `results`에 링크별로 `success`·`failed`·`duplicate`·`skipped`가 남고, 성공한 링크는 `useSourceStatus(source.id)`로 따로 폴링해요 |
| 5-2 보관함에 이미 있는 장소 | `useDuplicatePlaces(source)` | 분석이 끝난 응답의 `duplicatePlaces`로 판단. '네' `replaceWithNew`, '아니요' `discardNew` |
| 5-2 모든 항목 추출 실패 | `displayOrDash` | `PlaceCard`·`PlaceCardCompact`가 이름·요약·태그·주소가 비면 '-'로 보여줘요. 리뷰 수는 없으면 숨겨요 |
| 5-2 삭제한 카드 다시 만들기 | 서버 | 그 링크로 만든 카드가 모두 삭제됐으면 중복으로 묻지 않고 새 카드를 만들어요(가짜 응답에 구현) |
| 5-3 같은 기간에 새 계획 | `useCreatePlan` | `isPlanPeriodOverlapError`면 안내창. '네'면 isForced로 다시, '아니요'면 끝내요. `getOverlappingPlanTitles`로 겹치는 계획 이름을 보여줄 수 있어요 |
| 5-3 빈 일차 | `planDays.ts` | `setDayNodes(plan, i, [])`로 건너뛰고 `finishPlan`으로 마쳐요. 빈 일차가 하나라도 있으면 `status: 'draft'` |
| 5-3 계획에 넣은 카드 삭제 | `useDeletedPlaces(planId)` | 계획의 카드 id가 보관함 목록에 없으면 안내창. '네' `removeDeletedNodes`(노드를 빼고 저장, 남은 노드끼리 동선이 이어져요. 플랜B만 삭제됐으면 플랜B만 떼요), '아니요, 복구할래요' `restoreDeletedPlaces` |
| 5-4 기간 줄이기 | `useChangePlanPeriod` + `KeepDaysModal` | 줄이면 `keepCount`가 생기고 남길 일차 선택 창을 띄워요. 정확히 `keepCount`개 골라야 확인돼요 |
| 5-4 기간 늘리기 | `useChangePlanPeriod` | 늘어난 날짜는 빈 일차로 붙고 `status: 'draft'`로 바로 저장해요 |
| 노드 순서 변경 | `useUpdatePlan` | 화면을 먼저 바꾸고, 실패하면 되돌려요. 여러 번 빠르게 바꿔도 마지막 저장이 끝난 뒤에만 다시 불러와요 |

### FE가 가정한 서버 형식 (BE와 맞출 것)

| 무엇 | 가정 |
| --- | --- |
| 에러 응답 | `{ code, message, details }` |
| 중복 링크 | `POST /sources`가 409 `DUPLICATE_SOURCE`. 요청에 `isForced: true`면 통과 |
| 이미 있는 장소 | `GET /sources/{id}` 응답에 `duplicatePlaces: [{ newPlaceId, existingPlaceId }]`. 답하기 전에는 두 카드가 모두 보관함에 있고, 답하면 목록에서 빠져요 |
| 이전 카드 대체 | `POST /places/{existingId}/replace` `{ newPlaceId }` → 이전 카드 id가 남고 내용만 바뀌어요(계획의 노드가 그대로 이어지게) |
| 카드 삭제 | `DELETE /places/{id}`. 서버는 삭제 표시만 하고 남겨 둬요. `GET /places`에는 안 나와요 |
| 카드 복구 | `POST /places/{id}/restore` |
| 계획 상태 | `Plan.status: 'draft' \| 'complete'` (`isDraft`에서 바꿈) |
| 계획 만들기 | `POST /plans` `{ title, startDate, endDate, isForced? }` → 날짜마다 빈 일차가 든 draft 계획. 기간이 겹치면 409 `PLAN_PERIOD_OVERLAP`, `details.overlappingPlans: [{ id, title, startDate, endDate }]` |

### 기획에서 정해지지 않아 가정한 것

1. 추출 실패: 일부만 실패하면 '-'로 채운 카드, 전부 실패하면 기존 실패 화면(재시도·직접 입력)
2. 삭제한 카드: 서버가 삭제 표시만 하고 남겨 둬요. 계획에서 복구할 수 있고, 같은 링크로 다시 만들면 새 카드예요
3. 작성 중인 계획: 계획에 `status` 필드가 있어요. 작성 중 목록 화면은 아직 없어요
